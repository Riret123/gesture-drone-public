# Symbolic cost and capacity model

Round 02 response to B-01-02. All amounts: verify. Do not substitute guessed prices. The shortlist ranks local preparation value; there is no evidence-based revenue ranking.

For a software deliverable, define total cost C = authoring labor + review labor + support labor + distribution fees + payment fees + taxes/administration + contingency. Define net contribution N = receipts minus C. Unknown labor value is still a cost assumption, not zero.

For a physical kit, add components, failed prints, assembly, quality inspection, packaging, shipping, duties, returns, replacement inventory, insurance and safe disposal. Verify whether any item applies and obtain current quotes. A BOM alone is not unit economics.

Capacity constraint: accepted obligations must fit available study time after coursework and contingency. Recurring membership is not passive income if it creates regular delivery/support duties. A negative capacity estimate is a reason to defer, even if a spreadsheet shows hypothetical positive margin.

Sensitivity questions: what if support takes twice the measured trial time? What if a component is unavailable? What if no one pays? What if the product needs a refund? What if authorization or institutional IP review changes the permitted activity? The multipliers are stress questions, not predicted probabilities.

First-dollar timing depends on verified permission, an actual buyer or award, accepted terms and delivery/payment conditions. Write verify until those facts exist. Do not promise a time window based on an authoring schedule.

Disposition: ranking ambiguity fixed; monetary inputs, support burden and revenue remain UNVERIFIED.
