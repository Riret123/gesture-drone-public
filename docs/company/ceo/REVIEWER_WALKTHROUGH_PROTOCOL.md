# Five-minute reviewer walkthrough protocol

Round 02 response to C-01-03. Five minutes is a usability target, not an observed result. No actual reviewer timing has been collected in this run.

Setup: human reviewer has Python, the repository and no running ROS or hardware connections. Use OFFLINE_QUICKSTART.md. A facilitator may observe but must not silently correct instructions.

Tasks: identify which path can request real flight; identify which dashboard data is mock; run the portable suite; locate one test for malformed input; explain why a service acknowledgement is not completed flight; find one target validation blocker.

Observe: elapsed time per task, missing prerequisites, unclear terms, wrong turns and requests for help. Do not collect personal identifiers. Separate observed behavior from facilitator interpretation.

Success criterion: the reviewer finds the safe entry point and evidence boundaries without dangerous guessing. The five-minute target can be revised if the task set is too large. A slow walkthrough is a design finding, not a reviewer failure.

Failure response: clarify the document, repeat with a fresh reviewer if lawfully and appropriately arranged, and record the revision. No actual comprehension or accessibility claim is made before observation.
