# Claim labels for demos and portfolio pages

Use a visible label next to each feature, not only in a footer.

| Label | Meaning | Example permitted statement |
| --- | --- | --- |
| IMPLEMENTED / OFFLINE | local code exists without actuation | A JSON mission validator rejects malformed waypoint data. |
| TESTED / SYNTHETIC | named tests pass on generated inputs | A stale timestamp fixture is rejected by the offline policy. |
| TOY SIMULATION | model with stated assumptions | A moving-pad scenario completes in this kinematic model. |
| MOCK | fixed or synthetic source | This dashboard displays mock telemetry. |
| DESIGN | reviewed concept, no demonstrated integration | The lidar landing assist interface is proposed. |
| VERIFY | external evidence unavailable | Orange Pi dependencies and student income eligibility require verification. |

Never use autonomous landing, crash-proof, certified, real-time, accurate, commercially viable or production-ready without appropriately scoped evidence. A passing suite supports only the exercised cases. Service acknowledgement is acceptance of a request, not confirmation of a maneuver.

Acceptance: an unfamiliar reviewer can tell which data came from a camera, model or fixture. No public claim should silently inherit stronger evidence from historical notes.
