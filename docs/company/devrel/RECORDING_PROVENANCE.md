# Demo recording provenance

Response to D-01-03. A successful rehearsal is not evidence for a later source version. No recording is created by this document.

Every future recording should show or record date, OS/Python version, exact command, repository source snapshot identifier supplied by an authorized human, fixture identity, exit status and any cuts. This run does not run git commands to obtain identifiers. If no reliable source identifier exists, label it unknown.

Live output, previously recorded output and illustrative mockups must be labeled separately. Do not splice failure-free terminal output over a failed current run. If a command fails during a demo, preserve the failure and explain the next diagnostic step.

Keep credentials, personal identifiers, location-sensitive logs and unrelated windows out of frame. Use synthetic fixtures. A recording of a toy simulation does not become hardware evidence because it looks realistic.

Acceptance: a viewer can tell when and under what conditions an observation occurred. Provenance is a review aid, not certification.
