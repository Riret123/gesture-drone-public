Run the offline evidence

Use the repository root and the currently documented Python 3.12 environment. The portable suite uses the standard library.

Three safe entry points

  1. python -B tests/run_all.py

    Expected: named unittest results, final OK, exit code 0. The count changes as tests are added.

  2. python -B tools/landing_faults.py

    Expected: named proposal-level fault outcomes. Exit 0 means this limited campaign passed.

  3. python -B tools/simulate_landings.py

    Expected: JSON toy-model trial summary. A success rate here is a model result, not predicted aircraft reliability.

Keep test lanes separate. Do not substitute broad root discovery or the live bridge integration script. ROS package lint and isolated SITL are separate target tasks.

If something fails

Record the exact command, Python version, failing test name and traceback. Fix the regression before treating the batch as accepted. Do not connect a flight controller, suppress the test or change network configuration to make an offline check pass.
