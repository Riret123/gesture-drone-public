Инженерные доказательства и ограничения

Прототип передаёт запросы от распознанных жестов через ROS 2 и MAVROS. Отдельные Python-модули исследуют посадочную платформу, миссии и обработку отказов без управления реальным аппаратом.

Не армить настоящие моторы. Для осмотра стенда снять пропеллеры и отключить питание моторов. Снятые пропеллеры не означают разрешение на арминг. Эта страница не разрешает полёт.

Безопасный локальный запуск

Из корня репозитория, в документированной среде Python 3.12:

  1. python -B tests/run_all.py — переносимые unittest-проверки; ожидаются OK и код завершения 0.
  2. python -B tools/landing_faults.py — упрощённые сценарии отказов; это не реакция реального контроллера.
  3. python -B tools/simulate_landings.py — результат ограниченной модели, не вероятность успешной посадки настоящего дрона.

При ошибке сохранить команду, версию Python и traceback. Не подключать полётный контроллер для исправления локального теста.

Что важно различать

  • Запрос и подтверждение сервиса не доказывают завершение манёвра.
  • Искусственная телеметрия — не измерения с борта.
  • Упрощённая модель не подтверждает динамику реального аппарата.
  • Офлайн-геозона и арбитраж не защищают существующий ROS-мост.
  • Непрерывная открытая ладонь не является кнопкой deadman.

Нужны подтверждение среды Linux/ARM на Orange Pi, зависимости ROS/камеры, калибровка координат, изолированный SITL и отдельная оценка рисков. Здесь не подтверждены совместимость оборудования, точность посадки и качество перевода независимым техническим редактором.
